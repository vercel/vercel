Resolve explicit help requests (`vercel <cmd> --help`, `vercel help <cmd>`) before configuration or authentication setup, so help stays available when either is broken and regardless of where global flags appear in the invocation. Behavior changes, all intentional: explicit help exits `0` (command help previously exited `2`; `2` stays reserved for invalid or missing command structure, continuing #13780); help now wins over flag validation, so `vercel <cmd> --unknown-flag --help` prints help and exits `0` where it previously exited `1` with a parse error; help telemetry keeps the handler value shapes (`deploy`, `flags rules`, `env:list`, `flags rules:list`) but reports canonical command names where handlers sometimes reported user-typed aliases (`env:ls`), and events are emitted without the user/team/project attribution and context events of a full run. Telemetry is skipped entirely when consent state cannot be determined (unreadable or uninitialized config) — help renders regardless. The update notification is not shown for early-help invocations. Invocations consisting of only unknown flags (`vercel --prod --help`) and invalid nested command paths still fall through to the router, preserving previous routing and usage errors.
