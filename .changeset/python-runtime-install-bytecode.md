Bytecode-first packing for runtime-dependency-install builds (bundles over 225 MB that defer dependencies to a cold-start `uv sync`). When `VERCEL_PYTHON_COMPILEALL` is enabled, the zip now bundles only the mandatory set (app source, private packages, wheel-less packages, uv tooling) and defers every other public package to the cold-start install, spending the freed zip capacity on a `sys.pycache_prefix` bytecode tree (`_vc_pycache/`, exposed via `PYTHONPYCACHEPREFIX=/var/task/_vc_pycache`). The tree covers the app, bundled vendor packages, and the packages installed into `/tmp/_vc_deps` at cold start — since `uv sync --frozen` installs the exact locked versions the bytecode was compiled from, imports skip compilation even for `/tmp` sources. Bytecode-first packing falls back to the existing knapsack packing when the externalized set would not safely fit Lambda ephemeral storage (500 MB minus a 50 MB transient-wheel buffer); the knapsack path additionally gains a slack-capacity bytecode fill for in-zip packages, gated by the 50% coverage floor. With the flag disabled, behavior is unchanged.
