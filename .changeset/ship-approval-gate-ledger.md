'vercel': patch

`vercel ship`: deterministic approval gates and a session ledger, both driven by one environment variable (`VERCEL_SHIP_SESSION_DIR`) and plain files. Inside a ship session, commands that spend money (`integration add`, `domains buy`), touch production (`deploy --prod`, `promote`, `rollback`), or delete remote resources (`project rm`, `integration-resource remove`, `domains rm`) pause and ask the user for approval in the ship transcript before executing — the mission's spending rules become enforcement instead of prose. Every command also journals itself into `ledger.ndjson`, and effect sites (deploy, integration add, link, project rm, resource remove) record their outcomes from typed data, so the session's deployments and billable resources are reported from the machine's own record rather than scraped output, and the agent builds `teardown.sh` from the ledger rather than from memory. Ship also prepends a session `vercel`/`vc` shim to the agent's `PATH` that execs the very CLI entrypoint running ship, so a stale global install can never silently bypass the gate and the ledger. Teardown moved out of the mission entirely: after each turn ship prints the outcome summary and offers follow-up actions ("What next?") — teardown runs as a ledger-driven continuation turn in the same session, and the follow-up menu is the extension point for future actions. Approval prompts default to yes (Enter approves; the agent announced the step and the user is watching), a denial offers an optional steering line relayed to the agent verbatim ("no — use the existing database" instead of a dead stop), `--help` on a gated command is never gated, and agent-authored markdown in askUser prompts renders styled instead of leaking literal `**` markers.
