## 1. Nouns

Use these terms in help, prompts, output, and errors. They define human meaning; JSON keys and field values mirror the API. **Identity** lists the forms the CLI accepts as a selector; a mutation prints the first as its [stdout identifier](guidelines.md#streams). **Never say** lists synonyms that must not appear in user-facing copy, option names, or positional names.

- **One vocabulary across Vercel.** Spelling and casing match the Vercel dashboard's product glossary, so a term reads the same in the dashboard, docs, and CLI. When the two disagree, fix both; don't fork.
- **Label and prose forms.** Terms are Title Case in aligned labels, table headers, and help section titles (`Environment Variable`), and lowercase in sentences (`environment variable`), except the preserved-case names below.
- **Preserved case** (Title Case even in prose): Vercel, Vercel CLI (then "the CLI"), Production, Preview, Development, API Key, SDK Key, Rolling Releases, Global Config, Vercel Blob (then "Blob"), Vercel Sandbox, Vercel Firewall, Vercel WAF, Attack Challenge Mode, IP Blocking, Deployment Protection, Skew Protection, Vercel Queues, Fluid Compute, Observability, Web Analytics, Speed Insights, Spend Management, Hobby, Pro, Enterprise, AI Gateway, Vercel Agent, Vercel Toolbar, Instant Rollback, Deployment Checks, and the Environment Variable types Config and Secret. Role names are lowercase in prose (`team owners`, `a viewer`).
- **Command tokens may be short forms** of a noun (`routes`, `certs`, `env`, `vcr`). Prose always uses the full noun ("routing rule", "SSL certificate", "environment variable").

## 2. Verbs

A command's last segment is a verb from these tables, or a view leaf below. A new verb needs a row in the same PR and a reason no existing one fits. Each verb matches the dashboard's verb for the same action ([consequence verbs](guidelines.md#consequence-verbs)).

### Reading and changing

| Verb                 | Meaning                                                                                                                                                                        | Use instead of                                                            |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| `list`               | Read a collection                                                                                                                                                              | `ls` (alias), `show`, `get` (for many)                                    |
| `inspect`            | Read one resource in detail                                                                                                                                                    | `get`, `show`, `describe`, `info`, `fetch`, `view`                        |
| `create`             | Make a new standalone resource with its own lifecycle and ID (project, team, token, webhook, store, flag)                                                                      | `add`, `new`, `register`                                                  |
| `add`                | Put an existing thing into a container (a domain onto a project), or add an entry to a resource's configuration list (Environment Variable, DNS record, redirect, rule, label) | `create` (for these), `attach`, `install` (except the `install` shortcut) |
| `invite`             | Add a person who isn't a team member yet, by email or account                                                                                                                  | `add` (for people)                                                        |
| `update`             | Change the specified fields of an existing resource; omitted fields stay unchanged                                                                                             | `edit`, `patch`, `modify`, `change`, `configure`                          |
| `set`                | Assign a value to a named slot, creating or replacing it (`aliases set`, `flags set`)                                                                                          | `update` (when it's an upsert)                                            |
| `rename`             | Change a resource's name only                                                                                                                                                  | `update --name` (both MAY exist)                                          |
| `enable` / `disable` | Turn a feature or resource on or off without deleting it                                                                                                                       | `turn-on`, `on`/`off`                                                     |
| `move`               | Change a resource's position in an ordered list (`firewall rules move`)                                                                                                        | `reorder`                                                                 |
| `status`             | Read the current state of a singleton feature or operation that has no ID                                                                                                      | `inspect` (when there's an ID)                                            |
| `check`              | Run checks and report each result (`security check`, `cli versions check`)                                                                                                     | `verify` (for checks)                                                     |
| `search`             | Find items by query (`domains search`, `traces search`, `help search`)                                                                                                         | `find`, `lookup`                                                          |

- `create` or `add` depends on how the object is managed, never on its ID, nesting depth, or the word "rule". A webhook has its own lifecycle, so it uses `create`; firewall rules and flag targeting rules are entries in a configuration, so they use `add`: `vercel webhooks create`, `vercel firewall rules add`, `vercel flags rules add <FLAG>`.

### Ending and removing

Pick the verb that matches the real outcome; never soften (`remove` for a destroyed project) or overstate (`delete` for a detached member).

| Verb         | Outcome                                                                                                           | Reversible?               |
| ------------ | ----------------------------------------------------------------------------------------------------------------- | ------------------------- |
| `delete`     | Permanently destroys a resource and its data                                                                      | No                        |
| `remove`     | Takes a member or configuration entry out; the thing itself isn't destroyed, or it's only an entry                | Yes, add it again         |
| `disconnect` | Severs a connection to an external system or resource; data stays there                                           | Yes, connect again        |
| `revoke`     | Invalidates a credential or access; the record stays in history                                                   | No for the credential     |
| `empty`      | Deletes every item but keeps the container (queue messages, blobs in a store); `purge` is only for cached content | No for the items          |
| `rotate`     | Issues a new credential and invalidates the old one. If old versions keep working, it's `create` then `activate`  | No for the old credential |
| `cancel`     | Aborts an in-flight or scheduled operation                                                                        | Depends on the operation  |
| `stop`       | Halts a running resource so it can be started again                                                               | Yes                       |
| `transfer`   | Moves ownership to another team; the current team loses access                                                    | Yes, transfer back        |
| `leave`      | Removes the current user from a team                                                                              | Yes, if invited again     |

- Credentials: `revoke` when the record stays visible and invalid; `delete` only when the credential is removed from storage entirely.
- `dangerously-` prefixes a verb whose consequence is severe and unusual (`cache dangerously-delete`). It follows the severe [consent tier](guidelines.md#consent).

### Lifecycle verbs

| Verb                                                              | Meaning                                                                                                                      |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `deploy`, `redeploy`                                              | Create a deployment / rebuild a previous one                                                                                 |
| `promote`, `rollback`                                             | Point production at a deployment / at a previous one (prose: "roll back")                                                    |
| `build`, `dev`, `run`                                             | Build locally / serve locally / run a command or job now                                                                     |
| `link`, `pull`                                                    | Associate a directory with a project / fetch project state locally                                                           |
| `connect`                                                         | Attach an existing resource or external system (`git`, `storage`, integration resources, connectors); undone by `disconnect` |
| `publish`, `discard`, `restore`                                   | Make staged changes live / drop staged changes / return to a previous version                                                |
| `import`, `export`                                                | Bring many records in from a file / write them out                                                                           |
| `upload`, `download`, `copy`, `push`                              | Transfer bytes to or from Vercel / duplicate server-side / upload a container image (Docker convention)                      |
| `archive`, `unarchive`                                            | Retire without deleting / bring back                                                                                         |
| `pause`, `resume`                                                 | Suspend and continue serving or processing                                                                                   |
| `scale`                                                           | Override a resource's instance counts without changing its configuration                                                     |
| `restart`                                                         | Stop a running instance and start it again from the same configuration                                                       |
| `start`, `approve`, `abort`, `complete`                           | Rolling Releases stages                                                                                                      |
| `block`, `unblock`                                                | IP Blocking                                                                                                                  |
| `purge`, `invalidate`                                             | Remove cached content / mark it stale                                                                                        |
| `buy`, `renew`, `verify`, `claim`, `transfer-in`                  | Domain and marketplace lifecycle; `transfer-in` starts moving a domain's registration to Vercel                              |
| `reply`, `resolve`, `reopen`                                      | Comment threads                                                                                                              |
| `open`                                                            | Open a resource in the browser (dashboard, Toolbar)                                                                          |
| `capture`                                                         | Record a new sample of live behavior (a trace)                                                                               |
| `activate`                                                        | Make one version the active one among several (KMS keys, CLI versions)                                                       |
| `accept`                                                          | Accept legal terms                                                                                                           |
| `issue`                                                           | Have Vercel issue a certificate or credential                                                                                |
| `diff`                                                            | Compare two versions, or staged changes with live                                                                            |
| `apply`                                                           | Apply a batch of changes (from input or several options) in one operation                                                    |
| `split`, `rollout`                                                | Set a flag's weighted variant split / progressive rollout                                                                    |
| `prepare`                                                         | Generate build-time artifacts (flag definition fallbacks)                                                                    |
| `switch`                                                          | Change the current team                                                                                                      |
| `login`, `logout`, `signup`, `whoami`, `setup`, `upgrade`, `init` | CLI session and setup (prose: "log in", "log out", "sign up")                                                                |

- A verb is never fused with a noun (`create-store`, `add-key`, `list-versions`). Nest the noun as a group instead: `blob stores create`, `kms keys create`, `routes versions list`.
- A verb is never a positional value (`domains auto-renew example.com on`, `projects protection <enable|disable>`). Make it a subcommand: `domains auto-renew enable example.com`.
- The resource follows the action: `vcr permissions list my-app`, never `vcr permissions my-app list`.
- **View leaves.** A read-only leaf that prints one derived view or value MAY be named for it instead of a verb: `firewall overview`, `firewall bot-management`, `teams sso`, `teams request`, `metrics query`, `metrics schema`, `projects token`, `projects access-summary`, `integrations balance`, `integrations discover`, `integrations categories`, `integrations guide`, `activity types`, `flags override`, `flags evaluations`, `flags datafile`, `blob presign`, `blob signed-token`, `connectors token`, `connectors discover`, `connectors categories`, `agent-runs trace`, `agent-runs projects`, `ai-gateway models endpoints`, `ai-gateway leaderboard *`, `monitors schema`, `domains price`, `billing usage`, `billing contract`, `cli versions installed`, `cli completion`.
- **Operation status.** `status` MAY follow a lifecycle verb to read the state of that operation: `deployments promote status`, `deployments rollback status`. It behaves like `inspect`: no remote side effects, supports `--json`.
- **Workflow leaves** name what the workflow applies to: `setup mcp`, `setup ai-gateway`.

The hidden `deploy describe` subcommand prepares local deployment artifacts for external provisioning; it does not inspect a deployed resource. It takes `--deployment <DEPLOYMENT>` and `--aws-account-id <AWS_ACCOUNT>`, like `build --deployment` and `deploy continue --deployment`. `--id`, the BYOC extension's old name for `--deployment`, stays as a deprecated alias on all three.

## 3. Selectors and value hints

Name the same identity the same way everywhere. Positionals and value hints use the noun, never its type or API field name. A selector is named for the noun and NEVER ends in `-id` (`--store`, not `--store-id`). What it accepts is governed by [resource identity](guidelines.md#resource-identity).

| Identity           | Option                                                                | Positional       | Value hint       | Never                                                                                               |
| ------------------ | --------------------------------------------------------------------- | ---------------- | ---------------- | --------------------------------------------------------------------------------------------------- |
| Team               | `--scope` (global)                                                    | `<team>`         | `<TEAM>`         | `--team`, `--org`, `--slug` for a team                                                              |
| Project            | `-p, --project`                                                       | `<project>`      | `<PROJECT>`      | `<app>`, `<name>`, `projectId`, `NAME_OR_ID`, `PROJECT_ID`                                          |
| Deployment         | `--deployment`                                                        | `<deployment>`   | `<DEPLOYMENT>`   | `--dpl`, `--deployment-id`, `<url\|deploymentId>`, `-d`                                             |
| Environment        | `-e, --environment` (repeatable; also accepts a comma-separated list) | `<environment>`  | `<ENVIRONMENT>`  | `--target`, `--stage`, `TARGET`, `production\|preview`                                              |
| Git remote         | `--remote`                                                            | none             | `<NAME>`         | URL instead of an existing, case-sensitive local remote name                                        |
| Git branch         | `--git-branch`                                                        | `<branch>`       | `<BRANCH>`       | `--branch`, `--trigger-branch`, `-b`                                                                |
| Domain             | `--domain`                                                            | `<domain>`       | `<DOMAIN>`       | `<hostname>` for a domain                                                                           |
| Store              | `--store`                                                             | `<store>`        | `<STORE>`        | `--store-id`, `storeId`                                                                             |
| Installation       | `--installation`                                                      | `<installation>` | `<INSTALLATION>` | `--installation-id`                                                                                 |
| Version            | `--<noun>-version`                                                    | `<version>`      | `<VERSION>`      | bare `--version` (the CLI's), `--version-id`                                                        |
| Request            | `--request-id`                                                        | `<request-id>`   | `<REQUEST_ID>`   | `requestId`                                                                                         |
| Any other resource | `--<noun>`                                                            | `<noun>`         | `<NOUN>`         | camelCase (`ruleId`, `issuerId`), `-id` suffixes, `id` alone when the noun is known, `<name-or-id>` |

`--request-id` is the one `-id` exception: a request has no name.

Common value hints: `<NUMBER>`, `<TIME>` (ISO 8601 or relative), `<DURATION>` (`30s`, `5m`), `<PATH>`, `<FILE>`, `<DIR>`, `<URL>`, `<KEY=VALUE>`, `<CURSOR>`, `<TEXT>`, `<USD>`, `<PERCENT>`, `<JSON>`, `<NAME>`, `<VALUE>`, `<TYPE>`, `<FIELDS>`, `<PORT>`, `<LABEL>`. NEVER `<String>`, `<N>`, `<COUNT>`, `<MS>`, `<Boolean>`, or any hint that isn't listed here or named for a noun.

## 4. Standard options

Where a command has the capability (its API request or behavior supports it), it MUST use these names. An option for a concept not listed here (`--level`, `--expand`) is named for its field or noun in kebab-case and needs no row. Don't advertise an option before its behavior exists.

| Concept            | Option                                              | Rules                                                                                                                                                     | Never                                                                                                                                                            |
| ------------------ | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Machine output     | `--json`                                            | The only format selector. See [Machine Output](guidelines.md#10-machine-output).                                                                          | `--format json`, `-F`, `-j`, `--output json`                                                                                                                     |
| Consent            | `-y, --yes`                                         | See [Consent](guidelines.md#consent)                                                                                                                      | `--confirm`, `-c`                                                                                                                                                |
| Replace or re-run  | `--force`                                           | See [Consent](guidelines.md#consent)                                                                                                                      | `--overwrite`, `--allow-overwrite`, `-f`                                                                                                                         |
| Preview            | `--dry-run`                                         | Only with a real preview that performs no mutation                                                                                                        | `--plan`, `--preview`                                                                                                                                            |
| Variable injection | `--env <KEY=VALUE>`, `--build-env <KEY=VALUE>`      | Repeatable runtime / build values. Never an environment selector.                                                                                         | `-e`, `-b`. `deploy`'s legacy `-e KEY=VALUE` and `-b` migrate over two majors: they warn in major N, are removed in N+1, and `-e` means `--environment` from N+2 |
| Time range         | `-s, --since <TIME>`, `-u, --until <TIME>`          | ISO 8601 or relative (`1h`, `7d`); state the default window and timezone                                                                                  | `--from`, `--to`, `--start`, `--end`, `--date`                                                                                                                   |
| Result size        | `-n, --limit <NUMBER>`                              | Total results wanted; the CLI pages internally ([Collections](guidelines.md#collections-and-pagination))                                                  | `-l`, `--count`, `--top`, `--per-page`; `--limit` for money                                                                                                      |
| Continuation       | `--next <CURSOR>`                                   | Opaque cursor from the previous page                                                                                                                      | `--page`, `--cursor`, `-N`, numeric timestamps                                                                                                                   |
| Scope widening     | `-a, --all`                                         | Selects every item in scope (all projects; every entry for `remove`) or fetches every page (bounded, cancelable); one meaning per command, stated in help | `--team-level`, `--everything`                                                                                                                                   |
| Search             | `-q, --query <TEXT>`                                | Free-text search; define matching                                                                                                                         | `--search`, `-s`                                                                                                                                                 |

## 5. Short options

Each short option (`-` plus one case-sensitive letter) has **one meaning and one value type across the CLI**, except in `vercel api`. Short forms exist for frequent, low-risk inputs. Options that override safety or change what a command does (`--force`, `--dry-run`) never get one; `-y` is the one consent shortcut because it's universal.

| Short | Long              | Type    |
| ----- | ----------------- | ------- |
| `-h`  | `--help`          | boolean |
| `-v`  | `--version`       | boolean |
| `-d`  | `--debug`         | boolean |
| `-t`  | `--token`         | string  |
| `-S`  | `--scope`         | string  |
| `-A`  | `--local-config`  | string  |
| `-Q`  | `--global-config` | string  |
| `-a`  | `--all`           | boolean |
| `-e`  | `--environment`   | string  |
| `-f`  | `--follow`        | boolean |
| `-n`  | `--limit`         | number  |
| `-o`  | `--output`        | string  |
| `-p`  | `--project`       | string  |
| `-q`  | `--query`         | string  |
| `-s`  | `--since`         | string  |
| `-u`  | `--until`         | string  |
| `-y`  | `--yes`           | boolean |

- No other letter may be used. To reserve one, add it here in the same PR, with a reason it's needed CLI-wide.
- A command accepts a short option only if it has the capability: its API request or behavior supports that input. `-p` means project everywhere, or nowhere. A destructive or severe command rejects `-a`; `--all` must be spelled out.
- **Exception:** `vercel api` mirrors `gh api` (`-X` method, `-H` header, `-F` typed field, `-f` raw field, `-i` include headers) so that muscle memory transfers.

### Token Pass setup

`token-pass` is a top-level setup alias for `ai-gateway coding-agents setup --token-pass`. `tokenpass` is a spelling alias; an optional `setup` action runs the same workflow. Both forms forward gateway setup options and share its parser and help options.

`ai-gateway setup --token-pass` (also `ai-gateway coding-agents setup --token-pass`) automatically creates an immutable API key scoped to the team's Token Pass credits and models. Token Pass setup omits model selection and catalog guidance. Setup supports only `fx`, `opencode`, and `pi`: the picker, automatic detection, `--all`, and explicit `--agent` selection use the same set. Default key names retain the device/user scheme and include `token-pass`. Explicit `--key` reuse warns that the key must already be pass-scoped.

## 7. Keeping the registry true

This file drifts unless code enforces it. The target:

- **Metadata carries the registry.** Each command in `src/commands/*/command.ts` declares `noun` (a row in [Nouns](#1-nouns)), `action` (a row in [Verbs](#2-verbs)), `kind` (workflow, group, product, tool, shortcut, alias, deprecated), `context` (none, project, setup), `consequence` (read, ordinary, destructive, severe), `primaryStdout` (the identity it prints), and the `reason` codes it can emit.
- **The "Never" columns are lint-enforced** once this lint lands; until then reviewers check them.
- **A lint test walks `commandsStructs`** (`src/commands/index.ts`) and fails when: a leaf verb isn't in the verb tables; a group isn't plural or a product group listed in [Groups and products](#groups-and-products); a short option isn't in the registry or has a different type; an option uses a "Never" name from [Standard options](#4-standard-options) or [Selectors](#3-selectors-and-value-hints); a selector ends in `-id`; a value hint is a type name; aliases collide; an example doesn't parse; a list lacks `--limit`; a destructive or severe command lacks `--yes`; help text uses a "Never say" synonym.
- **A generated surface snapshot** (`vercel help --all --json`) is committed and regenerated in CI, so every surface change is visible in review.
- **Known violations** live in one exceptions list next to the lint test. It may only shrink.

Part of this exists today: `test/unit/commands/option-uniformity.test.ts` checks option names, `--json` coverage, legacy pagination and time-range names, `--since` and `--until`, `--next`, and `--yes`, and its allowlists are the exceptions list. Until the rest exists, reviewers check new and changed names against this file by hand.
